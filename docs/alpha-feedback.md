## 1. 使用体验记录（问题追踪）

| ID | 现象 | 复现 / 根因 | 处理版本 | 状态 |
|---|---|---|---|---|
| A1 | 顶部 UI 与通知栏 / 摄像头孔重叠；底部 tabbar 与手势条贴合不自然（edge-to-edge 适配缺失） | Android 15 强制 edge-to-edge；初版误用 `adjustMarginsForEdgeToEdge`（**Capacitor 7 配置，Cap 8 已移除**，无效）。alpha.3 用 `insetsHandling: native` 但**配置错放在 `android` 节点**（应为 `plugins.SystemBars`），无效。alpha.4 移到正确节点但**SystemBars 插件行为依赖 WebView 版本 / 加载时序，实机仍无效**。alpha.5 改为在 `MainActivity` 直接挂 `WindowInsetsCompat` 监听（确定性，不依赖插件） | alpha.2（误）→ alpha.5（方案） | **alpha.5 待用户验收**；若仍无效需 `adb logcat` 看 insets 实际数值 |

| A4 | 进入某故事发消息即报错 `(e.keys || "").split is not a function`，消息变孤儿回合 | 该角色卡世界书条目的 `keys` 是**数组**而非规范的逗号串（手工 / 转换工具构造的卡）；`matchLore` 对其调 `.split` 崩溃 | alpha.7 | ✅ 已修（两层防御：`normalizeLore` 入口归一 + `matchLore` 容错）；孤儿回合靠「重试」可恢复，已验证 |

## 2. 改进建议（用户已提及 / 测试暴露，待排期）

- **B1（关联 A1）**：边缘到边缘适配务必做对；状态栏 / 手势条避让区露出的窗口背景需与应用深色一致（已在 `styles.xml` 设 `windowBackground=#14161B`），验收时确认无白边。
- **B2（关联 A4）**：外部数据（手工 JSON、其他工具转换卡、全量备份）鲁棒性——除 `keys` 外，其他字段（`content`、`personality` 等）也应做形状防御与归一，避免下一处 `.split` / 遍历类崩溃。
- **B3（关联 A3）**：测试连接成功后，给用户「覆盖 / 合并」二选一（当前是「接口清单在前、与手填去重合并」），对网关类 `models` 返回不全的场景更可控。
- **B4（关联 A4）**：孤儿回合的错误恢复「重试」按钮体验良好，建议保留并补充「丢弃该回合」选项。
- **B5（移动端排查）**：设置页增加轻量「诊断」信息（当前 WebView 版本、`viewport-fit` 实际值、insets 数值），便于后续移动端问题自助定位，免每次 `adb`。
- **B6（UI 一致性）**：点击选择模型的子菜单与整体 UI 风格统一。**已确认（alpha.6 截图）**：模型选择用的是原生 `<select>`，展开时是**系统白底弹层**（黑字、系统选中圆点、系统字体），与深色金色主题严重脱节；同一弹层里的「协议」下拉（OpenAI 兼容等）也是原生 `<select>`，需一并统一。建议改为应用内自定义下拉组件（深色面板、金色高亮选中项、圆角/字号/动效与现有按钮和弹层对齐）；注意移动端触控目标高度与长列表（模型多时）滚动。

## 3. 后续开发想法（Backlog，未排期）

- **C1（已交付文档）**：角色卡规范 `docs/card-spec.md` 已建立，供开发者对照实现与校验。
- **C2**：独立角色卡**导出**格式——当前角色卡仅随全量备份 / 会话导出内嵌携带，缺独立导出入口。
- **C3**：事件钩子 / 时间线分支（已在 web 端批次 8/9 实现）待移动端完整验收。
- **C4**：状态栏 / 导航栏颜色随主题联动（当前避让区固定深色）。
- **C5**：移动端专属交互——下拉刷新、系统手势返回、本地通知/推送（若有后台任务）。
- **C6**：多模态——若后续引入图片生成 / 视觉理解，需考虑移动端权限与存储路径。
- **C7**：`feat/android-alpha` 分支合并到 `main` 的发布流程（含版本号、release notes）。
- **C8（导演指令 / 执导模式）**：**用户澄清语义**：不是「接入另一个 AI 来点评」，而是**用户作为导演，直接对皮下的扮演者（实际生成角色回复的那个 AI 模型）下达执导指令**——例如「你这里应该更冷淡一点」「改用更古风的文风」「先别揭穿他，吊着」。指令注入到 prompt 上下文，实时影响扮演风格与走向。**与角色卡设定的区别**：角色卡是「角色本身是谁」，导演指令是「用户对 AI 怎么演的要求」，二者解耦。形态设想：独立「导演」面板/输入框（折叠侧栏或弹层），指令以额外 system 注入或特殊角色消息注入每回合；支持多条累积、临时开关、单条删除；不污染角色对话历史（用户可见但 AI 不把它当剧情）。技术可复用现有 `compileMessages` / `custom prompt` 注入机制。变体：若日后想要「自检」，可在导演指令之外**可选**叠加第二个 AI 对扮演结果打分，但那不是用户当前的核心诉求。

## 5. B6 / C8 实施方案（2026-10-20 定稿，待授权）

### 5.1 B6 · 自定义下拉组件替换全部原生 select

**现状**：全局共 8 处原生 `<select>`（`ModelSettings.jsx` 6 处：对话默认模型的提供商/模型、编辑弹层的覆盖提供商/模型/协议/默认模型；`ChatView.jsx` ⚙ 弹层 2 处：提供商/模型）。

**方案**：新建受控组件 `src/components/Dropdown.jsx`（`options`/`value`/`onChange`/`placeholder`）：
- 触发器复用 `.input` 外观（同高度深色边框），右侧箭头
- 浮层深色面板（主题变量），**当前项金色高亮**、圆角、阴影，`z-index` 高于弹层
- 交互：点击开合、点外部 / `Escape` 关闭、`max-height` 滚动、选项行 ≥40px（移动端触控）
- 新增 `.dropdown` / `.dropdown-menu` / `.dropdown-item(.is-active)` 样式，与现有按钮/弹层动效对齐
- 全局替换 8 处 + 组件单测。**约 0.5 天**。

### 5.2 C8 · 导演指令（执导模式）

**语义**：用户直接指挥皮下的扮演者（怎么演、文风怎么改），指令注入 prompt 但不属于剧情。

**数据**（会话级，Dexie 普通新字段无需升版本）：
`session.director = { enabled: false, notes: [{ id, text, createdAt }] }`；随会话导出，旧文件读侧兜底。

**编译注入**（`compileMessages`）：注入在静态前缀之后、触发条目/记忆之前（指令稳定靠前利于缓存），格式 `## 导演指令（用户对扮演者的要求，不属于剧情内容）`；支持 `{{char}}`/`{{user}}` 宏；`enabled=false` 或空列表不注入；计入 system token 预算。

**UI**（ChatView）：顶部工具栏「导演」按钮（启用且有指令时带状态标记）→ 弹层含总开关、说明文案、指令列表（inline 编辑 + 删除）、快速添加、长度统计；对话流不显示指令内容。

**测试**：编译注入（启停/宏/空表）、sessionIO 往返、UI 交互。**约 1 天**。

**二期变体**（非当前诉求）：导演指令之外叠加第二 AI 自检评分。

## 6. 工程协作规范（项目管理优化 · 2026-10-27 落地）

> 来源：alpha.8→alpha.14「导演指令不生效」耗时 6 个构建，复盘后制定的防重蹈规范。

### 6.1 真实测试档案（每次修复只对此验证）
- **模型档位**：用户实跑 `flash / pro`（**非 chat**）；动手前先确认当前档位，禁止在 chat 上验证后宣称「已修」
- **推理**：pro 档开启，`max_tokens` 含思维链 → 默认上限偏低易截断；pro 建议 ≥4096
- **截断信号**：`finish_reason='length'` 时回复尾部丢失（探针常驻位置）
- **供应商 / Key**：用户本地配置，开发者环境无 Key → 真机往返项 与 本地可测项 必须分开排期
- **版本核对**：设置页页脚显示 `APP_VERSION`，报问题前先核对装机版本
- ⚠ 教训：alpha.8→alpha.13 在 chat 上验证，与真实档位不符，多轮白做

### 6.2 决策日志（试过什么 / 排除了什么，避免重辩）
按「症状」记条目；已回溯导演指令弧：
- 症状：导演指令不生效 / 325 探针时灵时不灵
- alpha.8：注入静态前缀 → 被长卡设定稀释（弱模型对前缀注意力低）→ **否**
- alpha.12：移动态块末尾 + 立即保存 + 返回键消费栈 → 解决「保存/注入链路」，但档位错配掩盖成效
- alpha.13：发现 `finish_reason` 在 client 被静默丢弃（截断无信号）+ flash 需绝对末尾 → 透传 finish + 末尾 system 提醒
- alpha.14：末尾独立 system 被推理模型 chat 模板丢弃 → 改末尾消息后缀；并补🔍诊断卡（直接看实际 prompt）
- 结论：根因 = 档位错配 + 截断无信号 + 末尾 system 被丢；**诊断卡应更早做（alpha.8 就该有）**

### 6.3 探针 / 验收信号规范
- 命令式，不写条件句（「如果…就…」弱模型判断不了前提）
- 可机械判定（输出固定串如 `325`，肉眼/脚本可验）
- 放在模型注意力最高的位置（prompt 绝对末尾）
- 进阶：app 内置「导演遵循自检」按钮一键跑探针（待授权）

### 6.4 下次同类「某功能不生效」4 问
1. 我验证的模型 / 配置，**等于**用户真实跑的吗？
2. 有没有一条**本地断言**能立刻判定「功能进没进 prompt / 进逻辑」？
3. 这 bug **必须上真机**，还是纯逻辑本地能拦？
4. 探针是否命令式、可机械判定？
